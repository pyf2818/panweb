隧道内核这件事，别人收费的地方它免费

panweb 的架构逆向自 UUMit 客户端（Go + 内嵌 fatedier/frp）： 隧道内核换成 Cloudflare 快速隧道，平台侧的账号、成员、实名与权限层整层去掉—— 零服务器意味着没有那台需要人守着的服务端。

UUMit

  • frp 隧道，服务端由平台自建
  • 平台账号 + 实名认证
  • 固定设备子域名
  • 暴露面分档：私有 / 邀请 / 成员管理 / 公开
  • 免费档 + 付费档

panweb

  • cloudflared 快速隧道，只出站连接
  • 无账号、无实名、不联网校验
  • 每次发布随机网址（可另接固定域名）
  • 靠随机子域名隐匿 + 访问口令 + 分享页 + 时效
  • 源码自托管免费；商业发行版一次买断

请求走的那条路

本机永远只发起出站连接，所以 NAT、防火墙、家庭宽带都能用； 源站只绑定 127.0.0.1，公网看不到它的地址。

  1. 01本机拉起 cloudflared，向 Cloudflare 建立出站隧道
  2. 02需要一个隧道就秒级取用一个：预热隧道池早就候着了
  3. 03直连发布把隧道指向应用端口；要口令、统计、分享页则先经过内置代理
  4. 04网址进状态文件，隧道独立进程存活——关掉终端也照样能访问

三条命令，覆盖三种东西

同一个控制台、同一批 core_* 函数也被 CLI、Web 界面、 MCP 与 Agent 技能共用，所以不会出现「界面上能做、命令行做不到」。

  • 控制台常驻时预热隧道池，命中约 1-2 秒出网址
  • 有效期可选 1 小时 / 1 天 / 7 天，到期自动收回
  • 已走代理的发布改口令不换网址，实时生效

隧道通了，页面却只有一个壳？这才是要害

      
静态页和简单应用发出去就能用。真正复杂的应用会给你两道意料之外的门：
        应用自己校验 Host 防 DNS 重绑定，以及应用要它自己的账号。panweb 1.5 把这两件事变成可诊断、可设置的东西。

      

        

          

          
⇄回源 Host 可切换

          
默认把本机地址交给应用（应用的防重绑定校验继续生效）；需要时切到 tunnel，
            访客正在用的公网域名原样传到上游，Jupyter、Grafana、n8n、Open WebUI、Vite 的「未知 Host」403 就消失了。

          panweb compat 我的应用 --host-mode tunnel
        

        

          

          
🔑代访客带上应用凭据

          
应用非要自己的 token 才能用时，本机代理替每个访客注入 Bearer / Basic / 自定义请求头。
            密钥只写进 ~/.panweb/secrets/<id>.auth.json（0600），
            状态文件、界面、命令行、MCP 和分享页最多只能看到「已设置哪种」。

          printf 'bearer\n' | panweb compat 我的应用 --auth-stdin
        

        

          

          
🔬按访客视角自检

          
发布后自动以访客身份真打开公网网址：首页状态与重定向链、首页引用的 js/css、一次裸 TLS 的
            WebSocket 握手。结论同时写进命令行、详情抽屉、应用卡和分享页——打不开就明说打不开。

    一台小机器上的完整发布台
    
      
    后端按职责分包，前端模块化组装；单文件体积由测试守住，不会出现一个 3700 行的巨型脚本。
    
      
    
        
    ⚡秒级网址
    控制台常驻预热隧道池与转发器，发布时直接取用；隧道 502/530/失联自动重建，网址抖动前先探测三轮。
    
        
    🪪分享页
    /__panweb/share/<token> 首屏给应用名、说明、有效期倒计时、在线状态和口令入口，带 OG 预览，适合直接发微信。
    
        
    📊匿名统计
    访客数与访问次数、分享页浏览与应用打开拆分、24 小时/7 天走势、设备与来源分布。IP 经本机 HMAC 后截断，不存原始地址与 UA。
    
        
    🌐固定域名
    自有域名接入 Cloudflare 后走命名隧道：授权、建隧道、写 DNS、绑定应用一条向导做完，网址永久不变。
    
        
    🤖Agent 与 MCP
    内置 MCP stdio 服务（9 个工具）与 Agent 技能；对 Claude Code、Codex 等说「把 3000 端口发出去」即可，技能里带安全规则。
    
        
    💻网页里的真终端
    控制台挂的是伪终端（PTY + xterm.js），不是聊天框：选本机已装的 Claude Code / Codex / OpenCode 和工作目录，以交互模式跑起来——彩色界面、进度条、分页器、Ctrl+C、↑↓ 翻历史都照原样，让它替你 discover → publish → check。
    
        
    🖥控制台与菜单栏
    仅绑定 127.0.0.1 的五页工作台：我的应用、动态与提醒、连接 Agent、终端、系统与数据；Swift 原生菜单栏常驻，深色模式与 ⌘K 命令面板。
    
        
    🔁健康自愈
    每 60 秒巡检：内置代理死亡自动重启（网址不变）、陈旧条目清理、孤儿进程按 PID + 命令行双重校验后回收。
    
        
    🧬诊断包与更新
    出问题一键导出脱敏诊断包（版本、环境、发布状态、动态、日志尾部）：凭据目录、口令、访客记录与许可密钥本体都不打包，出包前还会自审一遍。panweb update 在买断的 1 年窗口内取回新安装包，只落到本机并给出校验和——不偷偷替换正在运行的版本。
    
        
    🔐离线买断许可
    RSA PKCS#1 v1.5 + SHA-256 离线签名，14 天试用、默认 2 台设备、含 1 年更新；全程不联网校验，不采集使用数据。
    
      
    
    
    
  
    

  
    
    
    
      
    公开是它的价值，也是它的风险
    
      
    随机子域名是「隐匿」，不是「认证」。panweb 把边界写进代码，而不是写进承诺。
    
      
    
        
    控制台不会被发布识别并拒绝自己的 7788 与内部代理端口，避免把本机管理权限带到公网。
    
        
    高危目标先劝阻无密码的模型服务、数据库、管理后台、含个人数据的文件夹——发布前必须确认一次。
    
        
    静态发布有边界realpath + commonpath；拒绝隐藏文件、指向发布根之外的符号链接与系统根目录；只读。
    
        
    口令与注入防护加盐 SHA-256、常量时间比较、10 分钟 8 次失败限流；上游请求头拒绝 CR/LF，禁止覆盖 Host/Connection/Upgrade/Content-Length。
    
        
    子进程不经过 shellargv 数组启动，回收时校验 PID 与命令行，防 PID 复用误杀。
    
        
    只出站cloudflared 只向外连接 Cloudflare；本机不开放任何入站端口。

    命令一览
    
        
    panweb ui本机控制台（浏览器仪表盘）
    
        
    panweb discover扫描可发布的 HTTP 应用
    
        
    panweb publish <端口>发布正在运行的应用，--share 带分享页
    
        
    panweb pages <文件夹>文件夹发布成只读网页
    
        
    panweb run <项目>识别并自动启动，再直达公网
    
        
    panweb check <应用>访客视角自检与取证修正
    
        
    panweb compat <应用>Host 模式与上游凭据
    
        
    panweb list / stop / status查看、收回、总览
    
        
    panweb host <文件>Markdown/Excel 托管到 GitHub Pages
    
        
    panweb mcp以 MCP stdio 暴露 9 个工具
